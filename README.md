# Атмосфера Мебель

Сайт мебельной мастерской: каталог на 137 моделей, корзина-заявка,
ИИ-консультант и админка.

**Работает по адресу [atmospheremeb.ru](https://atmospheremeb.ru)**

---

## Как устроено

Сайт статический. Сборка превращает каталог и тексты в 148 готовых
HTML-страниц, которые веб-сервер отдаёт как есть — без рендера во время
запроса. Поэтому страница открывается быстро, а поисковик видит готовую
разметку, а не пустой блок с одним скриптом.

Живого на сервере ровно столько, сколько нужно: приём заявок, ИИ-консультант,
админка и статьи, добавленные через неё. Это одна программа на Go.

```
site/          исходники: шаблоны страниц, стили, скрипты, факты о компании
tools/         сборка и служебные скрипты
backend/       бекенд на Go — заявки, консультант, админка
deploy/        заголовки безопасности для nginx
public/        результат сборки: то, что раздаёт веб-сервер
data/          исходные фотографии и каталог (в репозиторий не входят)
build-data/    данные для бекенда, создаются сборкой
```

## Собрать

```bash
node tools/build-site.js
```

Кладёт страницы в `public/`, данные для бекенда — в `build-data/`.
Правьте `site/`, а не `public/`: содержимое `public/` перезаписывается.

Посмотреть результат у себя:

```bash
node tools/preview.js
```

Предпросмотр раздаёт `public/` с той же политикой безопасности (CSP), что
и nginx. Заявки и консультант в нём не работают намеренно — сервер заявок
один, это бекенд на Go, и копии его логики на Node больше нет.

**В разметке не должно быть `onclick="…"` и `<script>` внутри HTML** — их
блокирует CSP. Вместо обработчика пишите `data-click="имяФункции"`
(и `data-arg`, если нужен аргумент), а функцию добавьте в список
`ДЕЙСТВИЯ_РАЗМЕТКИ` в `site/core.js`.

## Где что менять

| Что | Файл |
|---|---|
| Сроки, цены, гарантия, регионы работы | `site/facts.js` |
| Телефон, почта, реквизиты | `site/contacts.js` |
| Тексты главной | `site/pages.js` |
| Остальные страницы | `site/pages2.js`, `site/pages3.js` |
| Шапка, подвал, меню | `site/layout.js` |
| Поведение ИИ-консультанта | `site/ai-prompt.js` |
| Политика конфиденциальности, согласие | `site/pages-legal.js` |
| Стили | `site/*.css` |

**Факты о компании живут только в `site/facts.js`.** Оттуда они попадают
и в тексты страниц, и в FAQ, и в промпт консультанта. Раньше они были
продублированы в шести файлах, и после смены условий сайт какое-то время
утверждал прямо противоположное в разных разделах одновременно.

## Бекенд

Одна программа на Go, без внешних библиотек в системе. Собирается в единый
файл и работает службой `atmosfera`.

```bash
cd backend && go test ./... && CGO_ENABLED=0 go build -o atmosfera .
```

Тесты покрывают то, что ломается незаметно: очистку разметки статей
от скриптов, очередь недоставленных заявок, лимиты, вход в админку.
Все переменные окружения перечислены в `.env.example`.

Что делает:

* принимает заявки с форм и из корзины, пересылает в Telegram и пишет журнал;
* отвечает за ИИ-консультанта (прокси к провайдеру, ключ наружу не уходит);
* принимает план комнаты картинкой и шлёт его в Telegram;
* показывает админку: заявки, блог, скрытие товаров и правка цен;
* собирает страницы статей, добавленных через админку.

Секреты — токен Telegram, ключ ИИ, хеш пароля админки — берутся из переменных
окружения, а данные лежат вне папки, которую раздаёт веб-сервер. Это важно:
когда файл с секретами лежит внутри раздаваемой папки, его закрытость держится
на том, что в конфиге веб-сервера не ошиблись.

Заголовки безопасности для nginx (HSTS, CSP и прочие) — в
`deploy/nginx-security.conf`, как подключать — написано внутри. Там же важная
оговорка про `location /admin/`: без неё общий CSP заблокирует скрипты админки.

## Админка

Адрес `/admin/`, вход по паролю. Пароль нигде не хранится — только результат
его прогонки через PBKDF2-SHA256.

Сменить пароль:

```bash
node tools/admin-password.js "новый пароль"
```

Команда напечатает `ADMIN_SALT`, `ADMIN_ITER` и `ADMIN_HASH` — их нужно
подставить в настройки службы на сервере и службу перезапустить.

Через админку можно скрыть товар, переименовать его, проставить цену
и добавить статью в блог. Правки применяются сразу, пересборка не нужна.
Описания и фотографии задаются в коде: добавление новых товаров через
админку не предусмотрено намеренно.

## Каталог

`data/catalog.json` — 137 моделей. Перекос сильный: 83 из них кухни,
поэтому в разделах главной «Кухни» занимают вдвое больше места, чем
остальные категории. Это не ошибка вёрстки, а отражение того, что есть.

Фотографии обрабатываются заранее и лежат в `public/img` в трёх размерах.
Оригиналы (93 МБ) в репозиторий не входят.
