# Атмосфера Мебель — как устроено и как выкладывать

## Коротко

Сайт **статический**: все 148 страниц — обычные HTML-файлы, собранные заранее.
Сервер их просто отдаёт, ничего не рендерит. PHP работает только на приёме
заявок и в админке.

Почему так, а не PHP на каждой странице: поисковик видит готовую разметку, сайт
одинаково работает на любом хостинге и не падает, если PHP отключат. Плюс всю
вёрстку удалось проверить локально — под рукой не было PHP, а отдавать
непроверенный серверный код неправильно.

---

## Что залить на хостинг

Заливается **содержимое папки `public`**, а не сама папка. В корне сайта
(`public_html` или что показывает панель) должны лежать `index.html`,
`catalog/`, `product/`, `img/` и остальное — без промежуточной папки `public`.

Объём — около 18 МБ, почти всё это картинки каталога.

**Формат картинок — AVIF, без запасного WebP.** Он вдвое легче при том же виде,
но Safari читает его только с версии 16.4 (март 2023): на более старых айфонах
фотографии не покажутся вообще. Решение принято осознанно, ради экономии места.
Если понадобится подстраховаться — вернуть запасной WebP через тег `<picture>`;
тогда на диске будут лежать оба формата, но каждый посетитель скачает только один.

В `.htaccess` для этого прописан `AddType image/avif .avif` — без него старый
Apache отдаёт файл как `application/octet-stream`, и браузер его не отображает.
В `server.js` то же самое сделано через `setHeaders`, чтобы локально
поведение совпадало с хостингом.

```
index.html          404.html           robots.txt        sitemap.xml
catalog/            kitchens/          living/           product/  (137 папок)
blog/               about/             contacts/         cart/
assets/             img/               data/             inc/
api/                admin/             config.php        .htaccess
favicon*.png        favicon.ico        og-image.jpg      site.webmanifest
yandex_b07ec57e06f76f0a.html
```

### Осторожно: папок `data` две, и это разные вещи

| Папка | Заливать? | Что внутри |
|---|---|---|
| `atmosphere-mebel/data/` | **НЕТ** | исходники для сборки: оригиналы фото на 91 МБ, описания товаров, пароль админки |
| `atmosphere-mebel/public/data/` | **ДА** | рабочие данные сайта: журнал заявок, статьи блога, правки каталога |

Заливается только вторая — она лежит внутри `public` и попадает на хостинг
вместе с остальным содержимым. Отдельно про неё думать не нужно.

**Не заливать:** папку `data/` из корня проекта, `node_modules`, `site/`,
`tools/`, `brand/`, `server.js`, `.env`. Всё это нужно только для сборки на
вашем компьютере. В `.env` и `data/admin-password.txt` секреты лежат
открытым текстом — на сервере их быть не должно.

## Права на запись

Папке `data` внутри корня сайта нужны права на запись — туда пишутся заявки
и то, что меняется через админку:

| Файл | Что это |
|---|---|
| `data/orders.log.php` | журнал заявок, его показывает админка |
| `data/blog.json` | статьи, добавленные через админку |
| `data/.htaccess` | закрывает папку от чтения через браузер — **обязателен** |
| `data/overrides.json` | правки каталога: скрытые товары, цены, названия |

Если админка пишет «Не удалось записать файл» — в файловом менеджере хостинга
поставьте папке `data` права `755`, а если не поможет — `775`.

## Админка

Адрес: `https://ваш-домен/admin/`
Пароль лежит в `data/admin-password.txt` — этот файл на хостинг **не заливается**.

Что умеет:

- **Заявки** — всё, что ушло в Telegram: из корзины, с форм, планы комнат.
- **Блог** — добавить, отредактировать и удалить статью.
- **Каталог** — скрыть товар с сайта, переименовать, проставить цену.
  Изменения видны сразу, пересобирать сайт не нужно.

Чего админка **не** умеет: добавлять новые товары и загружать фотографии.
Каталог собирается из данных в `data/catalog-meta.js` — это осознанное
ограничение, а не недоделка: фото нужно скачать, обрезать и тонировать, а это
делает скрипт сборки.

**Смена пароля:**

```bash
node tools/admin-password.js "новый пароль"
```

Скрипт выведет три строки — замените ими такие же в `public/config.php`
и залейте файл заново.

## Пересборка сайта

После правки текстов, каталога или вёрстки:

```bash
node tools/build-catalog.js   # данные каталога → data/catalog.json
node tools/build-site.js      # все HTML-страницы, CSS и JS
node tools/check-links.js     # проверка: битые ссылки, картинки, мета-теги
```

Затем заново залить изменившееся: обычно это `index.html`, `catalog/`,
`product/`, `assets/` и `data/catalog.json`.

Что где правится:

| Что менять | Файл |
|---|---|
| Товары, описания, характеристики | `data/catalog-meta.js` |
| Телефон, почта, реквизиты | `site/contacts.js` |
| **Факты о компании** (сроки, гарантия, цены, что входит) | `site/facts.js` |
| Промпт ИИ-консультанта | `site/ai-prompt.js` |
| Пункты меню, шапка, подвал | `site/layout.js` |
| Тексты главной | `site/pages.js` |
| Тексты «О компании», «Контакты», блог | `site/pages2.js` |
| Стартовые статьи блога | `site/blog-posts.js` |
| Стили | `site/components.css`, `site/layout-extra.css` |
| Тёмные секции главной | `site/dark.css` |
| Цвета текста и контраст | `site/contrast.css` |

Файлы `public/assets/site.css`, `site.js` и `planner.js` собираются
автоматически — править их бессмысленно, при следующей сборке всё затрётся.

## Единый источник фактов

Сроки, гарантия, состав стоимости, порядок работы и география лежат в
`site/facts.js`. Оттуда они попадают и в тексты сайта, и в системный промпт
ИИ-консультанта — он собирается в `public/data/ai-prompt.txt`, и этот файл
читают оба обработчика: Node локально и PHP на хостинге.

Так сделано после того, как одни и те же сведения оказались продублированы
в шести файлах, и после смены условий работы сайт какое-то время утверждал
прямо противоположное в разных разделах. **Меняйте факты только здесь**, потом
пересоберите сайт — тексты и промпт обновятся вместе.

Данные, помеченные в `facts.js` как `stub: true`, я не выдумывал. Про них
консультанту прямо запрещено говорить, а на сайте они не выводятся:

- год основания компании;
- имя руководителя;
- бренды фурнитуры и материалов.

Как только они появятся — впишите значение вместо `{ значение: …, stub: true }`,
и запрет из промпта уйдёт сам.

## Что обязательно заменить перед запуском

В `site/contacts.js` стоят **заглушки**. На странице «Контакты» они выведены
пунктирной рамкой, чтобы их нельзя было не заметить:

- телефон, почта, Telegram, WhatsApp;
- название ИП, ИНН, ОГРНИП, адрес регистрации, банк и расчётный счёт.

Замените на данные из документов ИП и пересоберите сайт.

## Безопасность: что закрыто и что проверить после заливки

### Персональные данные

Журнал заявок `data/orders.log.php` содержит **имена и телефоны клиентов**.
Он защищён двумя независимыми способами:

1. Файл назван `.php` и начинается строкой `<?php http_response_code(404); exit; ?>`.
   При запросе по прямой ссылке сервер его **исполняет** и не отдаёт ни байта
   содержимого. Это работает, даже если `.htaccess` почему-то не подхватится.
2. В `data/.htaccess` папка закрыта целиком, открыты только три файла,
   которые сайт действительно запрашивает из браузера:
   `catalog.json`, `blog.json`, `overrides.json`.

**Проверьте сразу после заливки:** откройте в браузере
`https://ваш-домен/data/orders.log.php`. Должна быть пустая страница или 404.
Если увидели строки с телефонами — на хостинге не работает PHP или не
подхватился `.htaccess`; в этом случае немедленно закройте доступ через
панель управления и напишите мне.

Тем же способом закрыты `ai-prompt.txt` (промпт консультанта) и
`admin-products.json` (служебный список для админки).

### Секреты

`config.php` хранит токен Telegram, ключ ИИ и хеш пароля админки. Файл
запрещён к отдаче в `.htaccess` и, как обычный PHP, при запросе ничего не
выводит. Открытого пароля в нём нет — только результат прогонки через
PBKDF2, обратно он не расшифровывается.

**Не заливайте** `.env` и `data/admin-password.txt` — там те же значения
открытым текстом.

### Админка

- Вход по паролю, сравнение хешей за постоянное время;
- пауза 0,4 секунды на попытку — перебор становится бессмысленным;
- кука сессии `httponly`, `samesite=Strict`, а по https ещё и `secure`;
- каждая правка требует токен формы, поэтому запрос с чужого сайта не пройдёт;
- страница закрыта от индексации и от встраивания в чужой фрейм.

### Сайт

- Ответ ИИ-консультанта экранируется перед выводом. Без этого посетитель мог бы
  через промпт-инъекцию получить ответ с работающим скриптом внутри.
- Адрес статьи в `blog/post.php` очищается до латиницы, цифр и дефиса —
  выйти за пределы папки нельзя.
- На приёме заявок, планов и чата стоит ограничение по частоте с одного адреса.
- В формах есть скрытое поле-ловушка: заполненное, оно молча гасит отправку.
  Бот думает, что всё прошло, менеджер спама не видит.
- Весь сайт принудительно переводится на https.

### Чего в проекте нет

Загрузки файлов, базы данных и регистрации пользователей — то есть нет и
типовых для них уязвимостей. Все данные либо собираются заранее, либо
пишутся админкой в JSON.

## Локальная разработка

```bash
node server.js     # http://localhost:3000
```

Node-сервер отдаёт ту же статику и повторяет все три API-эндпоинта, что и PHP
на хостинге. Админка локально не работает — для неё нужен PHP.

Секреты для локального запуска лежат в `.env`, для хостинга — в
`public/config.php`. Это два разных файла с одними и теми же значениями.

---

## Про фотографии каталога

Снимки взяты с сайтов сторонних мебельных компаний и обработаны под нашу
палитру. **Это чужая интеллектуальная собственность.** Для прототипа и
внутренней демонстрации это рабочий вариант, но при публичном запуске
коммерческого сайта остаётся риск претензии от правообладателя.

Правильное решение — заменить их собственной съёмкой или снимками, на которые
есть права. Замена делается без переделки сайта: положить свои файлы в
`data/photos-src`, прописать соответствие в `data/catalog-meta.js` и
пересобрать.

## Поисковые системы

Файлы подтверждения прав уже на месте, домен подтверждён в Яндексе и Google.
После заливки нового сайта стоит:

1. В Яндекс.Вебмастере и Google Search Console отправить `sitemap.xml`
   на переобход — адреса страниц изменились полностью.
2. Там же запросить переиндексацию главной.

Старый сайт был одностраничным, теперь у каждого товара свой адрес — это
148 новых страниц в индексе.
